# אפיון Backend — „הצעד הבא"

מסמך לאישור לפני תחילת הבנייה.

---

## א. תיאור הפרויקט

**שם:** הצעד הבא — מערכת מעקב מועמדויות לעבודה.

**מטרה:** לעזור לתלמידים מחפשי עבודה לנהל את המועמדויות שלהם, ולדעת בכל יום מה עליהם לעשות כדי להתקדם. מנהלי מוסדות יכולים לעקוב אחרי התלמידים שלהם, לעדכן עבורם מועמדויות ולזהות תהליכים שדורשים עזרה.

**משתמשים:**

| תפקיד | קוד במערכת | איך נוצר |
|---|---|---|
| מנהל ראשי | `SUPER_ADMIN` | אחד בלבד. נוצר מראש ב־Seed לפי משתני סביבה |
| מנהל מוסד | `INSTITUTION_ADMIN` | נוצר רק על ידי המנהל הראשי ומשויך למוסד |
| תלמיד | `STUDENT` | נרשם בעצמו ובוחר מוסד מרשימה. יכול להיכנס רק אחרי שמנהל המוסד אישר אותו |

**מחוץ להיקף:** חיבור לאתרי דרושים, שליחת דוא״ל, העלאת קבצים, צ׳אט, היסטוריית שינויים מלאה.

## ג. הרשאות

✅ = מותר  ❌ = אסור  🏫 = רק בתוך המוסד שלו  👤 = רק של עצמו

| פעולה | תלמיד | מנהל מוסד | מנהל ראשי |
|---|---|---|---|
| הרשמה עצמית | ✅ (כתלמיד בלבד) | ❌ | ❌ |
| צפייה ברשימת מוסדות להרשמה | ✅ | ✅ | ✅ |
| יצירה ועריכה של מוסדות | ❌ | ❌ | ✅ |
| יצירת מנהל מוסד | ❌ | ❌ | ✅ |
| צפייה במשתמשים | ❌ | 🏫 תלמידים | ✅ כולם |
| אישור / דחייה של תלמיד שנרשם | ❌ | 🏫 | ✅ |
| השבתה / הפעלה של משתמש | ❌ | 🏫 תלמידים | ✅ (לא את עצמו) |
| צפייה במועמדויות | 👤 | 🏫 | ✅ |
| הוספת מועמדות | 👤 | 🏫 עבור תלמיד | ✅ עבור תלמיד |
| עריכה ושינוי סטטוס | 👤 | 🏫 | ✅ |
| מחיקת מועמדות | 👤 | 🏫 | ✅ |
| הוספה, עריכה, סימון ומחיקה של פעולות | 👤 | 🏫 | ✅ |
| צפייה בתחומי תפקיד ובסטטוסים | 🏫 פעילים בלבד | 🏫 כולל לא פעילים | ✅ |
| ניהול תחומי תפקיד וסטטוסים של מוסד | ❌ | 🏫 | ✅ |
| שינוי הסטטוסים הבסיסיים | ❌ | ❌ | ❌ (קבועים) |
| קבלת התראות | 👤 | ❌ | ❌ |
| בחירת התחומים המבוקשים | 👤 | ❌ | ❌ |
| סינון תלמידים לפי תחום מבוקש | ❌ | 🏫 | ✅ |

**כללי אבטחה בשרת:**
- המשתמש המחובר נקבע **רק** לפי ה־Token, לא לפי מזהה שהלקוח שולח.
- גישה למועמדות של משתמש אחר מחזירה **404**, כדי לא לחשוף שהיא קיימת. פעולה שאינה מותרת לתפקיד מחזירה **403**.
- תחום התפקיד והסטטוס שנבחרים חייבים להיות שייכים למוסד של התלמיד (או להיות סטטוס בסיסי).
- משתמש מושבת, ממתין לאישור או נדחה אינו יכול להתחבר, וגם Token קיים שלו מפסיק לעבוד.

**מתי נוצרת התראה:** כשמשתמש אחר (מנהל) מוסיף מועמדות עבור תלמיד, משנה סטטוס של מועמדות או מוסיף לה פעולה, נשלחת התראה לתלמיד שהמועמדות שלו. שינוי שהתלמיד עושה בעצמו לא יוצר התראה.

## ד. תכנון מסד הנתונים

PostgreSQL + Prisma. שמונה טבלאות.

```
institutions 1──* users
institutions 1──* job_roles
institutions 1──* application_statuses   (institution_id ריק = סטטוס בסיסי)
users        1──* applications           (התלמיד שהמועמדות שלו)
job_roles    1──* applications
application_statuses 1──* applications
applications 1──* actions
users        1──* notifications          (מקבל ההתראה)
applications 1──* notifications
users        *──* job_roles              (דרך user_job_roles — התחומים שהתלמיד מחפש)
```

- התנתקות רגילה מתבצעת בצד הלקוח, במחיקת ה־Token מהדפדפן. אין צורך ב־Endpoint.

| שדה | טיפוס | חובה | הערות |
|---|---|---|---|

**אילוצים:** Primary Key משולב (`user_id`, `job_role_id`), כך שאי אפשר לבחור אותו תחום פעמיים. השרת בודק שהתחום פעיל ושייך למוסד של התלמיד.

**חישובים שאינם נשמרים בטבלה** (השרת מחשב לפי שעון ישראל):
- **באיחור:** פעולות פתוחות שתאריך היעד שלהן עבר.
- **להיום:** פעולות פתוחות שתאריך היעד שלהן היום.
- **בקרוב:** פעולות פתוחות ב־7 הימים הבאים.
- **ראיונות קרובים:** מועמדויות עם ראיון ב־7 הימים הבאים.
- **צריך לקבוע צעד הבא:** מועמדויות שהסטטוס שלהן אינו מסיים, ואין להן אף פעולה פתוחה.

## ה. Endpoints

כל הכתובות מתחילות ב־`/api`. „Token” = נדרש `Authorization: Bearer <token>`.

### כללי ואימות

| Method | URL | תיאור | הרשאה |
|---|---|---|---|
| GET | `/health` | בדיקת בריאות השרת ומסד הנתונים | ציבורי |
| POST | `/auth/register` | הרשמת תלמיד | ציבורי |
| POST | `/auth/login` | כניסה, מחזיר Token | ציבורי |
| GET | `/auth/me` | פרטי המשתמש המחובר, כולל `desiredJobRoles` | Token |
| PUT | `/auth/me/job-roles` | עדכון התחומים שאני מחפש `{ "jobRoleIds": [1, 3] }` — מחליף את הרשימה | תלמיד |

**דוגמה — הרשמה:**
```json
// Request
{ "fullName": "דנה כהן", "email": "dana@example.com", "password": "Dana1234!", "institutionId": 1 }
// Response 201 — ללא Token, כי החשבון ממתין לאישור
{ "message": "ההרשמה התקבלה. החשבון ממתין לאישור מנהל המוסד", "user": { "id": 3, "fullName": "דנה כהן", "email": "dana@example.com", "role": "STUDENT", "approvalStatus": "PENDING", "institution": { "id": 1, "name": "מכללת אופק" } } }
```
סיסמה: לפחות 8 תווים, כולל אות ומספר. שגיאות: 400 (ולידציה), 404 (מוסד לא קיים), 409 (דוא״ל קיים).

**דוגמה — כניסה:**
```json
// Request
{ "email": "dana@example.com", "password": "Dana1234!" }
// Response 200
```

| פרמטר | משמעות |
|---|---|
| `search` | חיפוש בשם החברה ובשם המשרה (ללא תלות באותיות גדולות/קטנות) |

| `sortBy` | `submittedOn` (ברירת מחדל) / `companyName` / `updatedAt` / `interestLevel` |
| `order` | `desc` (ברירת מחדל) / `asc` |
| `page`, `pageSize` | ברירת מחדל 1 ו־20 (מקסימום 100) |

## ז. טכנולוגיות ומסירה

- Node.js 22 LTS, Express, TypeScript (strict), Prisma, PostgreSQL, Zod, JWT, bcrypt, Swagger UI ב־`/api-docs`, Vitest.
- **Seed:** מנהל ראשי לפי משתני סביבה, שני מוסדות, מנהל לכל מוסד, שלושה תלמידים, תחומי תפקיד, סטטוסים ומועמדויות לדוגמה. בסביבת Production לא נוצרים חשבונות עם סיסמאות קבועות.
- **מספר Endpoints:** 36.
- **מסירה:** קובץ ZIP הכולל את הקוד, `START-HERE.md` (הוראות GitHub, מסד נתונים ו־Render בעברית) ו־`FRONTEND-API-GUIDE.md`. אין בו קוד React.
